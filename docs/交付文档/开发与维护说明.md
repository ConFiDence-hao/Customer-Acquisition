## 一、技术栈与运行模型

后端为Python与FastAPI，同步HTTP路由结合后台线程；服务由Uvicorn运行。持久层为Python标准库sqlite3和本地SQLite，未使用ORM、Redis、Celery或独立任务服务。前端为原生HTML、CSS和JavaScript，不需要Node构建或React编译。

requirements.txt固定依赖：FastAPI 0.135.1、Uvicorn 0.41.0、httpx 0.28.1、BeautifulSoup 4.14.3、Pydantic 2.12.5、pytest 9.0.2、pypdf 6.10.0、cryptography 46.0.3；续更新增Playwright 1.64.0、rapidocr-onnxruntime 1.4.4、NumPy 2.2.6、opencv-python 4.11.0.86、onnxruntime 1.22.1、Pillow 11.3.0与pypdfium2 5.14.0。pypdf用于PDF原生文字，PDFium用于扫描页本地渲染。README开发基线为Python 3.12；实际运行版本需在目标环境复核。浏览器二进制单独安装，Windows可使用系统Edge回退。Dockerfile采用固定digest的Python基础镜像，已加入Chromium系统依赖与libgl1，但本轮未构建验证镜像。

服务启动先验证必需配置并校准北京时间，再初始化数据库、来源、账号、个人任务及AI队列。网站采集、个人推送调度和AI队列都在同一个服务进程中协调。Docker启动命令使用单Uvicorn worker；进程内采集锁和调度线程不适合直接复制成多个worker，否则可能重复调度。需要横向扩展时，应先改造任务互斥、租约和调度归属。

数据库初始化启用WAL，每次连接设置外键，事务超时30秒。写入使用短事务，AI和网站HTTP请求不持有长时间数据库写事务。业务时间统一经app/clock.py提供，不能在新增业务逻辑中直接用宿主机datetime.now代替。

## 三、前端与后端协作

index.html提供登录壳、侧边菜单、主内容区、详情抽屉和通知入口。app.js提供共享状态、API封装、登录会话、列表筛选、详情及公共策略；workspace.js负责订阅编辑、模型和账号等管理；workbench.js负责系统配置概览、推送和自动任务；team.js与collaboration.js负责团队看板及责任变化。

querying.js显示扩展查询条件；assist.js把自然语言转为受限字段并直接执行查询或填入表单；jobs.js轮询持久任务；project-analysis.js显示报告和权限；diagnosis.js显示程序统计与AI解释；notifications.js轮询徽章；clock.js提供可信北京时间显示。

app.js的详情区为每条公告显示“项目摘要（规则生成）”“推荐依据（规则评分）”及“事实证据”，这些来自analysis等程序规则，不要求模型已调用。证据为空时显示暂无或待核实，不生成未经证实的采购字段。公共AI解读独立展示，已有结构化结果时显示model和generated_at；不能把规则摘要当成公共AI成功记录。详情同时显示覆盖警告、已知PDF页数和原文入口，不能用来源整体状态替代单条内容覆盖程度。

前端通过同源fetch传送JSON并携带Cookie。错误处理统一识别认证失效、超时、网络失败及服务端detail；客户端超时不等于后台任务已经取消。API响应不缓存，服务端按账号重新授权，不依赖隐藏菜单实现安全。

静态资源版本由服务端自动生成：index.html里的脚本和样式只写 /static/xxx.js，不要手写 ?v=。首页请求时 main.versioned_index 按每个文件内容的SHA-256前12位追加 ?v=，任一静态文件变化即重建；首页本身 Cache-Control: no-cache，带版本号的静态文件可长期缓存（immutable）。今日资讯翻页、筛选时复用60秒内的首页统计（state.dashboard），点“刷新列表”、从菜单进入或采集结束后重新统计。

页面状态使用会话代次、用户身份、渲染版本、抽屉版本和负责人版本判断异步结果是否仍适用。维护实时通知或AI轮询时，应保留这些校验，防止账号切换、项目转交或页面变化后把旧结果写到新页面。

通知可见页约15秒轮询，项目AI排队/运行时约2秒轮询。刷新责任信息时只修改必要元数据，避免重绘正在输入的私人备注、选择框或表单。表格每页提供5、10、20条，切换页大小回到第一页。

智能查询成功后自动提交当前查询表单，智能填写成功只更新草稿，不保存。对不支持的条件返回提示，不默默扩大范围；后台查询白名单和页面字段保持一致。不要新增只在AI提示词里存在、后端实际不支持的筛选能力。

## 四、数据库主要关系与数据边界

数据库默认位于data/radar.db，DATA_DIR可改变数据目录。初始化与迁移集中在各模块initialize函数，采用CREATE IF NOT EXISTS及必要ALTER TABLE，不是独立迁移框架。第一次创建账号时初始化管理员；旧全局跟进记录会迁移为管理员的个人记录；责任修订、默认主题与待检查记录用持久标记确保重复启动不覆盖用户修改。

| 表 | 关键关联与用途 |
|---|---|
| opportunities | 公共公告，URL唯一；列保存检索字段，payload保存公开正文、证据和分析元数据 |
| versions | opportunity_id关联公告，保存旧内容hash、payload和捕获时间 |
| sources | id关联来源标识，config保存规则；status、last_success、last_error、last_count记录运行情况 |
| runs、collection_progress | 采集轮次及run_id对应进度，详情保存各来源计数与耗时 |
| settings | 单行公共策略和采集计划 |
| companies | 可选业务名录；联系人信息不得送入AI任务 |
| users、sessions | 用户身份、角色与启用状态；会话只保存token哈希并关联user_id |
| subscriptions | user_id拥有的主题，config保存条件，enabled与deleted区分暂停和归档 |
| subscription_defaults | user_id与preset_id唯一，记录默认主题初始化关系 |
| subscription_checks | 每用户requested_revision和checked_revision，持久保存待重查请求 |
| automations | 每用户一条个人推送计划、上次成功执行和新增数 |
| pushes | user_id与opportunity_id唯一；payload保留首批送达快照及历史主题关联 |
| followups | user_id与opportunity_id复合主键，私人状态、note及更新时间 |
| team_followups | opportunity_id主键保证单负责人；保存owner_id、公开阶段、来源和owner_revision |
| team_followup_revisions | 即使放弃责任后仍保留递增版本，避免旧指派或旧AI结果生效 |
| notifications | 按user_id保存事件；user_id与event_key唯一，关联公告和负责人版本 |
| topic_analyses | 用户、订阅、公告复合主键；证据hash与主题hash确定个人报告有效性 |
| model_settings | 单行服务端模型设置及加密密钥 |
| ai_jobs | 持久任务、请求者、业务身份、可见性、输入/模型hash、状态、租约和结果 |
| project_analyses | 每公告一份共享项目报告，保留责任、证据、上下文及模型版本 |
| source_tests | 自定义来源测试令牌、配置指纹和过期时间 |
| audit | 管理、跟进及AI等操作审计 |

opportunities中的旧status和note列不能作为新的团队私密模型。输出公告时通过accounts.overlay叠加当前账号私人记录和公开团队信息；AI请求通过字段白名单构造输入，不读取历史全局私人备注。

公告内容hash排除详情抓取时间、分析日期及独立列表标题/渠道等易变元数据，避免缓存刷新制造不必要版本。相同内容更新last_seen_at；实际变化更新公告并保存旧版本。详情缓存不是单独表，位于公开payload中的content、detail_status、detail_fetched_at、list_title、listing_source_id等字段。

pushes保存首次送达及阅读状态，重复匹配只补充历史主题关联。推送详情结合当前公共证据，不能把首批快照当作永远不变的公告事实。团队看板不得把followups.note、topic_analyses或个人read_at混进团队结果。

## 六、采集、缓存、规则与预算

管理员手动或调度触发start_collection，RUN_LOCK保证同进程只有一轮。run_collection读取启用来源，内置来源调用分站适配器，自定义来源调用monitoring。候选经标题筛选、正文读取、证据分析后按URL入库，随后协调公共AI入队、活跃项目补查和个人推送。

有效订阅的关注词按所选来源扩展内置召回；全局排除词保留公共作用，个人排除词只影响本人主题。具备查询接口的来源可轮换检索词；仅栏目来源受公开页面窗口限制，不能声称每个关键词都会搜索全站历史。新库默认启用已适配来源，既有配置及管理员停用状态不因重启被覆盖。

内置PublicClient限定核验域名、HTTP/HTTPS标准端口、robots允许范围及公开访问。每主机请求间隔至少0.65秒；静态HTTP客户端保留500次调用预算，实际HTTP尝试另行累计，包含有限重试。连接超时10秒、一般超时22秒，一般响应大小上限4MB；已核验PDF入口使用独立get_pdf_bytes通道，输入上限20,000,000字节，访问及robots边界不放宽。401、403、429不绕过、不继续重试；网络或5xx只作有限重试。静态正文跳转拒绝，robots仅允许同源有限跳转，最多3跳。robots_rules.py补充通配符及路径规则匹配，不能因为标准RobotFileParser把星号当普通字符就读取实际被禁止的路径。

browser_fetch.py使用普通Playwright浏览器和独立上下文，不连接用户Chrome资料目录、登录态或现有标签页。默认每来源最多40个渲染页面，浏览器网络请求另限500次，并检查导航、最终页面和资源边界；该预算与静态HTTP的500次调用不是同一计数。站点脚本运行后只接受公开可见DOM，隐藏模板、导航、登录或验证码页面不能冒充正文。遇“安全认证”“IP存在访问异常”或需要人工验证时停止相应读取，不自动处理验证码、不代替用户登录、不收集会员隐藏字段。普通浏览器读到某条正文不表示该来源所有公告都可读。

本轮北极星bjx/gfcl在静态HTML或普通浏览器公开DOM中提取网页文字，取消其公告图片下载及图片OCR。正文容器发现图片时保留已有文字，记录图片参考和“公告图片未下载、未识别”的固定说明，按实际内容标partial或list_only；没有图片但文字不足120字符也保留真实文字并标覆盖不足。记录图片网址不代表已下载、已识别或已验证图片内容，用户仍从来源原文查阅图片。网页、验证及robots访问边界保持原样。

image_ocr.py仍用于三峰已适配的图片型正文，先核验文章和原图路径，再通过PublicClient读取允许的原图。原图域名独立核对robots；原图禁止自动读取与OCR失败分别分类。该图片OCR能力不等于接受任意网站、域名或附件。

三峰图片OCR单篇最多6张图，每图最多4,000,000字节、合计12,000,000字节，单图最多24,000,000像素；OCR在子进程执行，最长30秒，单篇下载与识别总预算45秒。识别使用CPU、线程数1，超时或未取得足够文字时保留线索与原图查阅信息。识别文字标记OCR来源，关键金额、单位和期限仍需核对原图；这些图片预算不适用于下面的PDF逐页提取。

首创公开PDF经已核验的同源附件入口读取，pdf_content.extract_pdf先用pypdf逐页提取原生文字，无文字页再由PDFium以144dpi渲染、交本地CPU OCR；不把公告页概况或导航冒充PDF正文。最多处理前30页、输入20,000,000字节（20MB）、输出65,000字符，提取进程总预算90秒，扫描页渲染上限24,000,000像素。每完成一页就输出进度，个别页失败继续后续页；达到时限终止进程后仍收集已输出的成功页，不因后页失败丢弃整份已取得内容。

PDF元数据包括pdf_pages_total、pdf_pages_read、pdf_ocr_pages、pdf_read_page_numbers、pdf_ocr_page_numbers、pdf_failed_pages、pdf_pages_attempted，以及pdf_truncated、pdf_text_truncated、pdf_timed_out和各项限制。页号从1开始，已读取/OCR页数只计有文字且成功的页；失败页号只列明确失败的页，不把未尝试页或超过上限的页伪称失败。总页数未取得就为未知，不用已读页数充当总页数。页数/字符截断、失败或超时按实际标记正文不完整，界面提供原文链接，缺失页需人工查阅。

本轮真实PDF验证：首创旧入库158795.html《宁河污水厂区房顶防水服务项目》中标结果公告为真实1页扫描PDF，pdf_pages_total、pdf_pages_read、pdf_ocr_pages均为1，content_coverage='complete'，本地OCR成功。另生成31页原生PDF验证只读取前30页并明确截断；这属于合成测试，不是真实网站31页公告。第47轮只对北极星两栏目、首创、大同各一条已入库线索作定向详情复核，共4条更新，不是完整四站采集：垃圾发电为partial且未下载/OCR公告图片，固废完整可读，首创扫描OCR完成，大同短正文为partial且可读。证据在 .venv/local-proof/pdf-partial-20261015/proof.json、31-page-proof.json、local-verification.json；不可推广为全部来源、全部PDF或完整采集验收。

大同仅从已核验.div-article2或.cs_xq_content > table.bid_msgTable提取正文，先排除nav、header、footer、script、style和noscript。真实短正文不足120字符也返回，raw写content_coverage='partial'、detail_status='正文不完整'及固定说明；没有正文返回空串并写list_only/仅列表线索。原标题、网址、已取得的发布日期和来源保留，缺失主体、预算或期限保持未知。网络、robots和验证异常仍抛SourceUnavailable，由采集总编排保留列表及独立记录访问问题；完整大同正文不覆盖默认完整状态，其他公共资源来源保持原解析要求。

content_coverage默认口径为complete、partial、list_only，分别表示按当前规则取得正文、仅取得部分内容和仅列表线索；字段缺省时根据是否有已采集正文作兼容判断。覆盖不足与来源访问故障分别统计和显示，不能把所有partial累加为网络错误或授权失败，也不能将partial正文描述为完整文件。extraction_warning解释具体缺失原因，未取得字段保持未知。

自定义MonitorClient重新校验公网URL与DNS，并固定已校验地址、保留Host和TLS身份，拒绝内网、本机、账号密码、令牌参数、异常端口及跳转。单来源最多60次请求、100秒，间隔0.65秒，响应上限4MB；配置最多4个同域补充列表页，每次最多40条候选。支持HTML选择器、RSS和JSON字段路径，规则保存与启用须满足测试指纹验证。

公告读取性能（2026年10月16日）：opportunities新增revision列，由触发器opportunity_revision在每次UPDATE时递增；db.PAYLOADS按(数据库路径,id,revision)缓存解析后的payload，db.unpack_many先只读轻量列、仅为缓存未命中的行读取payload。refresh_expired在库签名（行数、revision总和、最大id）未变、同一日期且尚无截止时间到期时跳过全表扫描。db.connect为每个数据库保持一个已读过数据的空闲连接，避免最后一个连接关闭时反复检查点并删除WAL文件，同时使用synchronous=NORMAL。企业名录导入见app/companies.py（POST /api/companies/import、GET /api/companies/summary，仅管理员可导入）。

成功正文缓存6小时，但列表每轮仍刷新。复用可接受正文至少120字符且状态正文可读的完整记录，或content_coverage='partial'、状态正文不完整且正文非空的记录；仅列表线索不作为正文缓存命中。两种复用均要求抓取时间不晚于当前且在窗口内、列表原标题和实际渠道一致，并保留覆盖字段与警告。旧记录没有独立列表字段时采用保守兼容判断。来源first provenance与当前listing渠道分开保存，不能用最终正文标题代替列表稳定性证据。

runs.details记录各来源found、inserted、updated、unchanged、restricted、elapsed_seconds、http_requests、cache_hits、detail_reads、listing_pages、listing_warnings、partial、list_only、coverage_notes，并可包含结构化issues。found是候选发现次数；静态HTTP、浏览器页面和资源请求的计数须区分；detail_reads是尝试读取数量，均不等于新增或可读正文数量。partial/list_only描述公告覆盖程度，coverage_notes说明缺失原因，与errors及restricted访问失败计数分开。restricted还可能包括触发限制后直接保留列表的剩余候选，并非每条都实际请求失败。跨频道同URL合并，observed_source_ids保留观察来源；跨站不同URL仍可能重复。

source_health.py只发布固定问题代码、标签和说明，例如ip_security_check、browser_budget_exhausted、ocr_image_blocked、ocr_failed与login_required；原始错误及其URL不直接作为公开说明。已注册并启用16个适配器只表示配置与代码存在，运行是否成功须看本轮健康状态、issues及具体样本，不能把启用数当成可用网站数。

## 七、可信时钟、身份与写入保护

clock.py从固定三个公开HTTPS来源读取Date头：中节能、环保在线和中国固废网。样本要求成功状态、非重定向、往返不超过2秒、缓存Age不超过2秒；至少两来源在3秒内一致，取中位数锚定UTC，再通过单调时钟推进并转换北京时间。

首次校准预算8秒，失败会阻止应用继续正常初始化，不静默退回宿主机业务时间。正常每900秒核验，异常失败约每60秒再尝试；可信核验超过6小时后进入只读保护，停止写入和新业务任务。HTTP变更方法统一校验时钟，数据库authorizer也逐条拒绝写语句；cached_statements=0避免旧缓存绕过时钟过期。

已校准时钟纠正采用渐进方式并防止业务返回值倒退。维护历史异常时要区分旧宿主机约6小时偏差与校准后新记录，不能直接批量重写首次采集、推送或历史版本时间。运维判断当前时点应读取/api/clock，/api/health正常不代表时钟已可信或所有来源正常。

密码用scrypt加盐哈希，会话token只存SHA-256哈希，Cookie为HttpOnly、SameSite=Strict；COOKIE_SECURE用于HTTPS部署。会话有效7天，改密码、角色或启用状态会撤销会话。登录失败按客户端限制，5分钟内达到10次失败返回429。跨站变更请求拒绝，响应设置CSP、防嵌入和无缓存等头。

SESSION_SECRET至少32字符，并参与外部模型密钥的Fernet派生加密；迁移时必须保留，否则旧外部密钥无法解密。公开模型配置只返回has_key，不返回真实密钥。外部模型地址仅允许公网HTTPS标准443端口的兼容Base URL，不含/chat/completions、账号或查询参数。

## 八、个人推送、AI任务与通知权限

调度循环每15秒判断公共采集计划，处理个人推送和项目补查。SCHEDULER_ENABLED=false暂停该循环，不等于停掉AI worker，也不禁止管理员手动采集。启动生命周期仍初始化AI队列并补查活跃项目，测试或隔离开发必须同时使用独立数据库和安全模型配置。

个人匹配统一使用subscriptions.match_decision，推送诊断复用同一谓词，避免诊断与实际投递口径不同。修改主题登记requested_revision；推送在提交事务前复核账号、计划和最新修订，过时结果丢弃。成功后才更新last_run与checked_revision，失败或重启不丢失待检查请求。

推送在匹配之后再经过subscriptions.push_decision：排除截止/结果/终止（订阅阶段明确勾选结果类阶段除外）、发布超过PUSH_WINDOW_DAYS=30天（无发布日期按首次采集UNDATED_PUSH_DAYS=7天）及仅正文命中且标题非核心方向或分数低于50的公告。workbench.dispatch_due通过subscriptions.deliverable应用该门槛，subscription_diagnosis按同一函数统计push_filtered及原因。PATCH /api/pushes/read-all可按subscription_id批量标记已读。

公共AI只有管理员可提交；自动批次门槛固定85分、每轮最多5条并且要求未有公共解读。专题报告为请求账号私有。项目报告只由管理员或当前负责人查看、触发，使用当前负责人业务配置与公开证据，不读取其私人备注。跟进中或已联系为自动活跃阶段；私人浏览、个人专题分析或普通员工未领取的私人保存不产生团队责任。

85分仅是公共自动AI批次的入队条件，未改变手动公共AI、个人专题AI或跟进项目AI的触发条件与权限，后者不受此公共自动阈值限制。每条公告的规则摘要、评分依据和事实证据独立生成，不能以是否存在summary判断模型是否运行；公共AI结果的模型和生成时间应以ai_analysis.model、ai_analysis.generated_at为准。保留界面的规则标识与AI元数据，避免把规则功能误称为全量AI分析。

ai_jobs持久保存queued、running、succeeded、failed、waiting_config、stale等状态。去重键含任务类型、可见性、身份、公告/订阅、责任版本、输入及模型hash；提交与结果发布都复核权限。负责人变化、主题/证据变化及模型变化使旧任务失效，不能将旧结果发布给接手人。

运行时启动8条worker线程，但数据库claim按配置限制实际并发，默认1时按ID串行；管理员可设1至8。并发大于1时前台优先、后台老化防饥饿，后台同时最多1项。租约180秒，监控约15秒续租并恢复过期running任务；网络执行期间不持有SQLite写事务。

模型请求为兼容Chat Completions接口，任务输出需JSON结构校验。内部当前调用有有限网络/截断恢复策略和时间预算，和失败任务重新入队是两回事。相同后台输入失败后不自动无限重试；用户显式重试重新检查身份、责任和证据。旧同步接口最多等待约15秒，超时可以返回任务编号，任务仍可能继续。

notifications对事件做安全字段白名单及每用户唯一去重。管理员通知仅展示普通员工claimed/released，不展示每次阶段更新；项目研判当前没有注册失败通知回调，不自动发送AI失败通知。普通员工指派需责任版本与当前负责人一致；只有真正显示项目详情后才确认当前指派已查看，通知收件箱阅读不能替代确认。

共享项目报告、个人专题报告和私人备注必须持续分离。新增AI类型时同时设计请求授权、运行验证、结果发布、失效条件及可见性，不能只新增前端按钮。

### 3. 只读诊断与备份

纯数据审计优先使用sqlite3的mode=ro URI及PRAGMA query_only=ON，仅选择授权字段。不要把app/db.py的通用连接当成保证无写入的审计接口：部分GET路径会刷新截止、初始化任务概览或处理状态。

维护CLI提供python -m app.cli init、collect、status、backup。init和collect明确写数据库，collect会请求公开来源；只在没有采集进程活动的维护窗口执行。CLI直接采集不等同main.run_worker的完整后续AI和推送编排，不能把两者验收口径混用。

SQLite处于WAL模式时，应使用SQLite备份API产生一致性快照，或停止写入后正确处理数据库及日志文件，不能随意只复制radar.db。备份需与代码、配置和镜像形成同一可恢复版本，恢复演练在隔离目录进行。
