## 一、系统解决什么问题

工作台把公开网站中的招采公告和行业资讯汇入共享资料库，再按每个账号的业务主题进行匹配、站内推送和跟进。它帮助使用者发现需求信号、核对采购证据、明确团队负责人，并把个人研究和团队进展放在同一条公告上查看。

日常工作可以理解为五步：管理员维护公开来源；系统采集公告；员工设置个人订阅；个人任务从共享库匹配并推送；员工核实原文后领取并跟进。AI是辅助环节，不是采集或订阅匹配的前提。模型关闭或暂时不可用时，公开资讯、规则匹配、站内推送和手写跟进仍可使用。

系统保存的是公开公告与线索，不能把每条记录都理解为可成交的客户机会。中标、终止和较旧公告可以用于竞争研究或后续合作；资讯可以提示建设动态；仅列表线索需要补查正文。不同网站转载同一内容时，仍可能保留多个不同网址。

“今日资讯”是日常入口，展示共享资料库，不代表页面中只有当天发布的公告。需要只看今日或近七天时，请使用公告发布日期条件。公告发布日期、首次采集时间、最近更新和收到推送时间是不同概念。

## 三、菜单与权限

左侧菜单分“工作空间”和“系统管理”两组：

- 工作空间：今日资讯、推送列表、我的跟进。
- 系统管理（管理员）：团队看板、系统配置、监测网站、推荐策略、智能化配置、账号配置。
- 普通员工的第二组显示为“个人设置”，只有系统配置、监测网站（只读）和账号配置。

账号由管理员开通，没有公开自行注册入口。普通员工不能修改公共采集网站、推荐策略、模型连接或团队账号。管理员也有自己的订阅、推送列表和我的跟进，并非只有管理页面。

## 四、主要功能

### 1. 今日资讯：查找和核实公告

页面顶部是四项统计：高优先级商机、有效跟进线索、累计情报和目标企业（名录企业数）。翻页或调整筛选时统计在一分钟内复用，点“刷新列表”或从菜单重新进入会重新统计。

今日资讯提供方向、区域、公告阶段、本人跟进状态、最低分和排序等筛选。方向包括智慧焚烧、烟气提标、控制系统、设备技改及其他；公告阶段包括招标、询价、采购意向、变更、中标候选人、中标结果、终止及资讯。跟进状态与公告阶段不同：前者描述个人或团队工作进度，后者描述公开采购流程。

可以按公告发布日期范围、多个相关关键词和截止情况进一步筛选。多个查询关键词支持任意命中或全部命中。日期按北京时间解释；不知道发布日期的记录不会被当作今天发布。列表可以切换匹配度、最新发布或截止时间优先；每页可选5、10或20条，支持跳页。

页面中的“仅有效商机”对应规则标签 actionable：系统取得正文、识别明确且未到期的投标期限，并满足阶段、报名期限等规则。它不证明供应商有资质，不证明该采购是本企业核心业务，也不等于中标概率。分数用于排序和筛选，不能替代原文核实。

点击公告打开右侧详情，可查看采购主体、区域、发布时间、投标截止、文件获取或报名截止、预算信息、首次采集、推荐依据、风险、下一步和结构化事实证据。每条详情都有“项目摘要（规则生成）”“推荐依据（规则评分）”和“事实证据”区块，均由程序从已采集内容生成；缺失信息显示未知或待核实。金额性质、资格与期限仍须打开“查看来源原文”核实。

单条公告的内容覆盖分为 complete、partial 和 list_only：分别表示按当前规则取得正文、仅取得部分内容、仅取得列表线索。后两种会在详情中显示“内容采集不完整”、具体说明和来源原文入口。

部分网站需要浏览器运行页面脚本后才能显示正文，系统使用独立后台浏览器读取允许公开的页面，不读取员工浏览器登录态，不自动登录或完成安全验证。图片型正文和扫描PDF在允许下载时进行本地OCR；PDF最多读取前30页，部分页失败仍保留已完成页并标明。OCR识别出的金额、单位和期限须核对原图或原附件。

已识别报名截止但投标仍未结束时，系统会提示新进入条件受限。发现同标段后续变更、结果或终止公告时，原公告不能直接当作当前投标依据。

“导出CSV”导出当前筛选条件下的记录，供工作整理使用。导出结果不扩大账号权限，也不是网站全部公告或市场总量。

### 2. 系统配置：个人主题订阅

进入“系统配置”的“订阅情况”，可查看主题是否启用、当前匹配数量和累计站内推送，通过“新建订阅”或“编辑订阅”打开表单。订阅名称用于识别主题；目标行业和产品服务能力用于说明业务背景；实际匹配仍以关键词与筛选条件为准。

关注关键词按文字包含匹配，公告标题或已取得的正文包含任一关键词即可进入后续条件判断。个人排除词只检查标题。地区、来源和公告阶段是进一步限制；留空地区表示全国，不勾选来源表示全部已接入来源，不勾选阶段表示全部阶段。

首次补齐四个预置主题：智慧焚烧与燃烧优化、烟气净化与排放提标、自动化控制与智慧管控、飞灰处置。预置主题可以修改、暂停或归档；系统重启不会恢复被主动修改的规则。预置主题不占用每账号最多50个自建订阅的限额。

“预览匹配结果”只使用已经入库的公共公告，帮助判断规则是否过宽或过窄，不立即执行网站采集，也不立即生成推送。保存且启用的订阅关键词会参与已接入来源后续的候选筛选：例如绿色动力平台上的“飞灰外运”“垃圾吊大修”类公告，只有在有订阅包含相应关键词时才会被收入。

归档订阅后，主题不再参与后续匹配，历史推送仍保留。停用某来源不会抹掉历史公告。

### 3. 自动化任务：采集和推送分别配置

普通员工在“系统配置→自动化任务”只配置“我的订阅推送任务”。该任务从共享库检查本人启用订阅，匹配后生成站内推送；不会因为员工调短间隔就抓取更多网站。

管理员同时看到“网站自动采集任务”，它按公共周期读取已启用来源，更新共享库。两种任务都通过“配置任务”打开表单，支持启用或停用，执行间隔范围为15至10080分钟。概览展示最近成功执行、最近新增推送和下次计划。

新建或修改订阅、启用订阅及启用个人推送计划会登记一次待检查请求，通常在下一次约15秒的调度检查中处理。同一账号同一公告只推送一次；后续补上另一个匹配主题时，不重复制造送达记录。所以“上轮新增为0”可能表示相关公告已经收到。

### 4. 推送列表与推送门槛

推送比订阅匹配更严格。匹配结果仍可在订阅预览和今日资讯中查看，但只有同时满足以下三条的公告才进入站内推送：

1. 仍然有效：未截止，不是中标候选人、中标结果或终止公告，也没有同标段后续公告。若在订阅“公告阶段”中明确勾选了中标结果等阶段，对应结果类公告仍会推送。
2. 足够新：公告发布在最近30天内；发布日期未知时，按首次采集在最近7天内。
3. 标题相关：关键词出现在标题中；仅在正文命中时，标题须属于核心业务方向，且不是常规维护、耗材类采购。

推送列表是本账号的站内收件箱，可以按主题、关键词、阅读状态、公告发布日期、收到推送日期和截止情况筛选。“全部标为已读”在选定主题时只标记该主题的未读推送。

推送诊断入口：在订阅情况中打开主题说明，点击“查看推送诊断”；或推送列表选定主题且无结果时。诊断区分账号或订阅停用、个人任务暂停、系统调度暂停、首次尚未检查、来源不可运行、库内无匹配及已由其他主题送达，并单独显示“匹配但不推送”的数量和原因（已截止或结果类、过旧、仅正文弱命中）。筛选漏斗依次查看来源、地区、阶段、关键词及标题排除词；“仅去掉此条件”只是调整预览，不自动修改规则。可点击“AI解释这些统计”获得较易理解的建议。

### 5. 我的跟进、负责人和私人备注

我的跟进汇总本人保存的研判记录以及当前由本人负责的公告。未领取项目时，保存状态与备注只建立个人记录；其他人仍可以主动领取该公告。

核实公告并决定负责后，点击“开始跟进”。每条公告同时只能有一位团队负责人；领取成功后进入“跟进中”，负责人姓名、公开阶段和更新时间对团队可见。其他员工不能抢占已有负责人，需要联系管理员转交。常用状态为待研判、跟进中、已联系、已排除和已归档。

负责人可点击“放弃跟进”，公告回到没有团队负责人的状态，原私人研究记录保留。管理员可以放弃他人负责的线索，或在详情中指派、转交。管理员派发的项目显示“管理员派发”和“新指派”，左侧“我的跟进”徽章统计尚未查看的派发项目。

### 6. 通知和团队看板

顶部“通知”与左侧“我的跟进”是两个徽章：前者表示站内通知未读数量，后者表示尚未查看的管理员派发项目。页面可见时大约每15秒刷新。

普通员工可以收到管理员指派或负责人转交等项目通知。管理员通知列表只展示普通员工领取、放弃或拒绝任务的事件。项目AI失败不会自动产生失败通知。

管理员“团队看板”分为订阅运行和跟进进展，可按账号或状态筛选和分页，不展示员工私人备注、个人专题AI报告或个人阅读详情。

### 7. 监测网站

监测网站以卡片展示每个来源的采集入口、采集逻辑、采集范围、最近状态和失败原因，可按网站类型（集团采购、公共资源、行业门户、商业聚合、前期公示）、接入状态和关键词筛选。卡片分页显示，每页6、12或24个；启用、停用或保存某个网站后，页面保留原来的类型、筛选和页码。普通员工只能查看。

管理员可启用或停用已适配来源，或添加自定义公开来源（HTML、RSS 或 JSON 规则，须先测试预览再保存启用）。

### 8. 推荐策略与企业名录

推荐策略设置公共重点词、全局排除词、优先区域和推荐最低分，保存会重新计算已有公告；采集进行时请等待完成再保存。

**企业名录是目标客户名单**，即全国垃圾焚烧厂的项目公司及其集团、省份、城市、规模、联系人。系统采到公告后，会把标题和正文与名录中的企业名称逐一比对，完全一致才算命中，命中后：

1. 识别采购单位：公告未写明采购人时，用命中的名录企业补上；
2. 补全区域：标题没有地名时（如“密云公司……招标”），用名录登记的省份和城市补上，区域筛选和优先区域加分随之生效；
3. 提高推荐分：命中名录加8分；
4. 统计：首页“目标企业”显示名录企业数，名录面板显示匹配到的公告数。

导入入口在推荐策略页底部“企业名录”（仅管理员）。导入是固定规则解析，不经过大模型，内容不发送给任何模型服务：

| 规则 | 说明 |
|---|---|
| 文件格式 | .xlsx（读第一个工作表）、.csv（UTF-8 或 GBK 编码）、.json（企业对象数组）；旧版 .xls 须先另存为 .xlsx；最大10MB、2万家 |
| 表头定位 | 在前10行中找含“企业名称”的行，表格上方可以有标题或说明行 |
| 必填列 | 企业名称（也认公司名称、焚烧厂名称、项目公司等） |
| 可选列 | 所属/隶属集团、省份、城市、地址、焚烧炉数/规模、投产/投运日期、联系人/信息公开负责人、联系电话；其他列忽略 |
| 清洗 | 企业名称去空格；空名称跳过；重名只保留第一行；省份统一为简称；Excel 日期数字自动转为日期 |
| 生效方式 | 整体替换现有名录，然后对全部公告重新比对；约3000条公告需1～3分钟，期间请勿关闭页面 |

名录联系人仅保存在本系统数据库，不纳入代码仓库，也不发送给模型。直辖市等未填城市的企业，公告只能补到省份。

### 9. AI解读、项目研判和智能辅助

公共AI解读由管理员生成，作为公告共享参考。管理员在“智能化配置”启用自动解读后，采集后只把公共分数85分及以上、尚无公共AI解读的公告加入后台队列，每轮最多5条。管理员手动生成公共AI、专题AI和项目AI不受85分门槛限制。

专题AI解读结合选定订阅的行业、产品服务和关键词生成个人解释，和公共解读分别保存。AI不会更改公开事实、分数、负责人或跟进状态。

项目AI研判由管理员和当前负责人共享，其他员工不具备查看和触发权限。领取、指派或转交，或负责人保存“跟进中”“已联系”时可自动排队。报告不把私人备注作为模型输入；证据、负责人、业务主题或模型变化后，旧报告可能显示“需更新”。

模型连接在“智能化配置”中设置，三种运行方式：

| 运行方式 | 适用 | 填写要求 |
|---|---|---|
| 外部 API | DeepSeek 等公网服务 | 公网 HTTPS 地址（443端口）、模型名、密钥；出于安全考虑不接受内网地址 |
| 本地模型 | 公司内网部署的模型（vLLM、Ollama、Xinference 等 OpenAI 兼容服务） | 内网地址，http 或 https、任意端口，以 /v1 结尾，如 http://10.0.0.10:8000/v1；填写模型名，密钥可留空。不能填 localhost 或 127.0.0.1（系统在容器中运行，那指向系统自身），请填模型所在服务器的局域网 IP。地址留空时使用服务器 .env 中的 LLM_BASE_URL |
| 关闭模型 | 不使用AI | 规则推荐、推送和跟进照常 |

切换运行方式时，地址和模型名会清空，避免把外部服务地址误存为本地模型；切回原方式可看到已保存的值。保存后点“测试已保存连接”确认可用。输出格式选“JSON Schema”要求模型服务支持严格结构化输出，不支持时选“JSON Object”或“普通文本”。

AI任务持久保存并排队执行，并发数可设1至8（当前为8）。失败会保留原有内容，不自动反复重试；项目面板显示失败后可点击“重试研判”。

智能查询把自然语言转换成当前页面支持的条件并直接执行，例如“查近七天江苏的控制系统招标，最低60分”。智能填写用于订阅、策略、网站、模型、账号、任务间隔等表单，只填草稿，最后仍须点击原表单的“保存”；密码、角色、密钥由本人手动填写。

### 10. 账号配置

左侧“账号配置”一个入口：

- 所有人：“我的账号”页查看显示姓名与角色，修改密码（至少12位，修改后需重新登录）。右上角账号菜单的“账号详情”也进入此页。
- 管理员：多一个“团队账号”标签，创建账号、编辑显示姓名与角色、停用账号或重置密码；编辑后该账号旧会话立即失效。至少保留一位启用的管理员。

## 五、常规员工上手操作

### 第一天：建立个人工作区

1. 使用管理员分配的账号登录，在“账号配置”确认显示姓名与角色；修改初始密码后重新登录。
2. 进入今日资讯，先把最低分和日期条件调整到便于观察的范围，了解共享库中有哪些来源与公告阶段。
3. 在“系统配置→订阅情况”核对四个预置主题，把宽泛词改成具体产品、工艺或需求词。
4. 填写产品服务能力；不要把尚未具备的资质写成既定事实。
5. 先保持全国、全部阶段和全部已接入来源，点击预览观察结果，再逐步缩小范围。
6. 确认关键词和排除词后保存，检查主题已启用。
7. 在“自动化任务”启用个人推送任务并选择间隔，确认没有“定时执行已暂停”提示。
8. 到推送列表查看首批推送。没有结果时打开主题推送诊断，判断是没有入库匹配、尚未检查、被推送门槛过滤，还是已通过其他主题送达。

### 每天：筛选、核实和跟进

1. 在推送列表处理新推送，用“全部标为已读”清理已看过的主题。
2. 在今日资讯按近七天、未截止、相关方向等条件补充查找；找历史或合作线索时不要只保留未截止公告。
3. 逐条打开拟跟进项目，核对采购范围、采购单位、截止、报名条件及最新变更。
4. 查看公共或专题AI建议，区分原文事实、业务建议和待核实问题。
5. 尚在研究时保存个人状态和备注；确认由自己负责时再点击“开始跟进”。
6. 在我的跟进中记录下一步和核实结果；收到“新指派”时打开详情确认负责人、阶段和期限。
7. 项目AI失败时在面板重试一次；如提示等待配置，请告知管理员。
8. 定期归档已完成研究的个人记录，停用不再需要的订阅。

## 六、管理员上手操作

### 初次配置

1. 在“账号配置→团队账号”新建员工，设置显示姓名、角色及初始密码，通过组织认可的渠道交付。
2. 到监测网站查看29个来源的接入状态、覆盖说明和最近采集；登记了网址不等于已有可用采集器。
3. 对已适配来源选择启用或停用；自定义来源先测试预览，再保存启用。
4. 在推荐策略设置公共重点词、排除词、优先区域和推荐最低分；在页面底部导入或更新企业名录。
5. 在自动化任务中分别配置公共采集计划和自己的个人推送计划。
6. 在智能化配置选择外部 API、本地模型或关闭模型（见第四章第9节），保存后测试已保存连接。

### 日常运营

1. 看采集记录中的发现、新增、更新、耗时及限制原因。发现数量是来源候选数，不等于新增项目数。
2. 来源“部分可用”时阅读限制说明，避免把验证页或导航内容误认为正文。
3. 在团队看板查看订阅停用、任务停用、来源不可用及零匹配主题，指导员工调整规则。
4. 处理员工领取和放弃通知，安排指派或转交。
5. 账号离岗时停用账号，并处理仍由其负责的项目。
6. 名录有新增或更正时重新导入整份文件（整体替换）。
7. 模型故障时先保留规则任务，再检查模型配置和连接测试。

## 七、常见问题

| 现象 | 应如何理解和处理 |
|---|---|
| 今日资讯中有很旧的公告 | 共享库包含历史记录；按公告发布日期筛选，并核实采购阶段 |
| 订阅预览有结果但没有推送 | 推送门槛只推新近、有效、标题相关的公告；打开推送诊断查看“匹配但不推送”的原因 |
| 想收到中标结果类推送 | 在订阅“公告阶段”中明确勾选中标候选人或中标结果 |
| 关键词命中却不属于核心业务 | 包含匹配会命中背景描述，须按标题及正文确认采购范围 |
| 公告区域显示待核实 | 标题和正文没有地名，且未匹配到名录企业；可补充名录或打开原文核实 |
| 导入名录时页面等待较久 | 需对全部公告重新比对，约1～3分钟；完成后名录面板显示企业数和匹配公告数 |
| 名录某些列导入后为空 | 列名不在可识别范围内；按第四章第8节的列名调整表头后重新导入 |
| 列表可见而正文为空或不完整 | 查看覆盖说明；可能只有列表、部分网页文字或PDF部分页，须打开原文核实 |
| 北极星多数公告只有标题 | 详情页有人机验证，系统不处理验证码；请打开原文查看 |
| 来源显示IP安全认证或需要登录 | 当前采集环境未取得允许读取的正文；系统不自动验证、不使用个人登录态 |
| 已投标未截止却不能新报名 | 文件获取或报名可能已截止，需核实此前手续 |
| 保存备注后团队没有负责人 | 私人保存不会领取，需主动开始跟进或由管理员指派 |
| AI排队时间较长 | 并发受限或模型较慢；原有证据和记录仍可使用 |
| 时间提示写入暂停 | 北京时间尚未可信核验；等待校准恢复并由维护人员检查 |
