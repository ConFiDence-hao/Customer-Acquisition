# 智能工作流分阶段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement the linked plans task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地派发红点、受控 AI 队列、管理员与负责人共享研判、查询直接执行、填写直接填入和推送诊断。

**Architecture:** 分为三个可分别验证的子计划：派发提醒先形成可使用界面；AI 基础设施建立准确时钟、任务调度和共享报告；查询与诊断复用统一任务接口。保留当前功能分支的全部已有修改，使用现有 FastAPI、SQLite 和原生前端，不新增部署中间件。

**Tech Stack:** Python 3.12、FastAPI、SQLite、HTTPX、原生 JavaScript/CSS、pytest、CUA 浏览器核验。

**Spec:** [智能工作流设计](../specs/2026-10-14-direct-ai-workflows-design.md)、[北京时间设计](../specs/2026-10-14-beijing-clock-design.md)。用户已认可方案并进一步确认侧栏红圆圈数字、管理员派发标记及团队负责人展示；本计划仍需评审和选择执行方式。

## Global Constraints

- 只实现和验证本地；不修改 178 服务，不提交凭据、数据库或备份，不推送或部署。
- 保留既有工作区修改，不 reset、不清理未跟踪源码；测试用独立临时 SQLite，浏览器核验用合成数据隔离服务。
- 智能填写自动填入并可撤销，仍手动保存；账号密码、API Key、权限、启停不由模型填写。
- 项目 AI 仅管理员和当前负责人可读／生成，手写备注及原有专题研判仍私有；负责人版本跨放弃持续递增。
- 派发红圈只统计当前本人负责人版本的未查看管理员派发；打开列表不清数字，详情成功清对应版本，超过 99 显示 99+。
- 默认模型并发 2、后台自动任务并发最多 1、可设 1–8；每次总时限 120 秒、响应最多 2 MiB、最多 3 次尝试，明确截断最多升预算重试一次。
- 查询与租约共用准确北京时间；不修改系统时钟，不固定加六小时，不改原公告发布时间及历史采集时间。
- 每阶段先验证必要行为、再实现、再跑相关检查和本地单文件范围提交；不能仅凭 agent 报告宣称通过。完整检查与最终浏览器核验完成后才宣布功能完成。

## Review Focus

- A→B→A 或放弃再领取：旧 AI 结果和旧查看确认不得发布或清新红点；子计划 A 的版本测试及 B 的项目 CAS 测试覆盖。
- 移动端通用 span 样式：红圈不能随图标隐藏；子计划 A 的浏览器桌面／移动验收覆盖。
- 生成过程中改字段、切账号、页面刷新：旧结果不能覆盖新草稿；子计划 C 的延迟响应验收覆盖。
- 跨北京时间日期的相对查询：缓存不能复用旧范围；子计划 B 的时钟边界与 C 的查询有效期测试覆盖。
- 现有私人数据：不能因新增共享项目报告变成团队可见，也不能进入通知或模型输入；子计划 B 的双用户报告与 C 的诊断测试覆盖。

## 实施顺序与接口边界

1. [A：派发提醒与负责人版本](2026-10-14-assignment-notifications.md)。独立交付红圈、来源标记、指派／领取提示，提供负责人版本和安全通知接口。
2. [B：时钟、AI队列与项目研判](2026-10-14-ai-runtime-project-reports.md)。读取 A 的负责人版本，统一 provider，自动生成授权项目报告及完成通知。
3. [C：直接查询、填写与诊断](2026-10-14-direct-assist-diagnosis.md)。使用 B 的任务接口和 A 的界面保护，补齐查询过滤条件及推送解释。

- [ ] 按子计划顺序完成；某阶段不通过时先修本阶段，不扩大真实模型调用。
- [ ] 最终执行 `.venv\Scripts\python.exe -m pytest -q`、相关 JavaScript `node --check` 和 `git diff --check`，确认完整输出和退出码。
- [ ] 在隔离服务验证双用户指派、红圈、共享报告、自动填写撤销、直接搜索及诊断；保存实际页面截图。
- [ ] SQLite 一致性备份与 `.env` 私有备份完成后更新本地 8000 服务；核验健康、两种角色和状态，保留回退文件。

## 执行方式待选择

推荐主助手直接实施各阶段，再由独立审查者复核整轮改动，优先尽快交付红圈效果；也可选择逐任务分工实施并逐项独立审查。选择与本计划评审完成前，不开始修改产品代码。
