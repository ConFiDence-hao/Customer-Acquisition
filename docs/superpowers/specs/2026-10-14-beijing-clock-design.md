# 北京时间统一时钟设计（待评审）

## 目标与已确认约束

应用在 Windows 本地开发及 Linux/Docker 部署中都使用准确北京时间。用户明确要求不依赖错误的本机时间；不修改 Windows 或服务器操作系统时钟，不固定增加六小时。此次偏差是诊断证据，不是永久配置。采集、推送、评分、期限、登录会话与页面日期必须共用同一个时间基础。

当前数据库已采用 `+08:00`，Docker 已设 `TZ=Asia/Shanghai`；时区正确仍不能保证时间准确。当前散落的 `datetime.now()` 会导致只改记录时间、未改期限判断的混用。

## 方案选择

推荐新增单一 `app/clock.py` 时间入口：从固定 HTTPS 来源取得 UTC 时间样本，校验后建立 UTC 与单调时钟的锚点，再统一转换为北京时间。现有 HTTPX 和 Python 标准库即可完成，不增加需要安装或运行的系统授时进程。

服务器标准 NTP/NTS 校时仍适合作为部署环境保障，但不作为应用唯一正确时间来源。此次不引入自实现、未经认证的 UDP NTP 客户端；NTP 诊断结果仅作为交叉验证。

## 校准与运行规则

- 来源由开发维护固定 HTTPS 白名单，初始候选为已核验的中节能慧采云、环保在线和中国固废网公开入口；实现前逐一验证 HEAD 响应时间、缓存与可用性，只启用通过验证的入口。不发送用户凭据、订阅内容或私有业务数据。
- 保留 TLS 证书验证；拒绝跳转、非成功响应、缺失或非法 Date、缓存超过两秒、往返超过两秒的样本。三个不同站点中至少两个样本的 UTC 时间须在考虑传输时间后相差不超过三秒，否则校准失败。取一致样本的中值；与系统时钟的偏差只作为诊断字段。
- 首次最多八秒完成校准，必须在数据库初始化、过期重评和后台线程启动前完成。首次无法校准时明确报错，不用错误的本机时钟启动正常业务写入。CLI 采集与分析也必须先校准；纯备份可使用不改业务记录的离线流程。
- 业务读取时间只访问内存锚点，不执行网络请求。后台每十五分钟核验；校准失效时沿用本进程最后可信锚点并显示降级状态。持续六小时未成功核验，暂停新的采集、推送和业务写入，保留健康诊断，直到恢复可信校准。
- 不将单调时钟锚点持久化或跨进程复用。检测系统休眠或时间异常后重新核验；只根据本机时间与锚点的差值变化触发核验，不直接采用本机值。确认的新时间样本不可让同一进程业务时间突然倒退，调整应平滑且暴露偏差状态。

## 改动边界

`clock.now_datetime()` 提供带时区的北京时间，`db.now()` 保留原有秒精度 ISO 字符串接口及 `+08:00` 格式。统一以下调用点：

- 数据库采集、更新、版本、推送、跟进与审计时间。
- 公共评分新旧程度、公告与文件期限，以及个人主题当天加分。
- 登录会话的创建、过期和校验；监测规则测试令牌的有效期。
- 全局采集与个人推送到期、180天回看和六小时正文缓存。
- AI 提示中的当前时间、报表及采集 CLI。
- 前端通过后端时间与 `performance.now()` 展示当前日期；已有时间字段继续显式按 `Asia/Shanghai` 格式化。

登录限流、HTTP 礼貌间隔、超时和单来源执行预算继续采用单调计时。公开健康接口只提供校准状态和时间；详细来源与偏差仅管理员可见。容器保持非 root、只读与原有能力限制。

## 历史数据与切换

切换前创建一致性数据库备份。原网站 `published_at`、deadline 及原文证据保持原值；已有 created/read/pushed/audit 时间也不进行无依据的批量平移。历史记录的错误时基可通过诊断说明追溯，首次推送证据保持原样。

旧会话和测试令牌依据新时间正常过期或重新取得，不统一延长期限，也不无条件清空所有七天会话。先确认无采集正在执行，再切换服务；恢复后每个到期计划只正常检查一次，不补跑过去六小时的每一轮。

校准后需要一次规则重评，修正之前“未来发布时间”的扣分与风险，以及真正已到期的状态。同一日的 `analysis_date` 不能保证触发重评，因此使用明确的迁移标记或分析版本升级。私有跟进、团队归属、阅读状态和首次推送时间保持原样。

## 验证与验收

先用固定假时钟和 HTTP fixture 验证：本机慢六小时仍输出正确北京时间；网络读取不进入数据库事务；样本不一致、缓存、超时、TLS 失败和跳转被拒绝；刷新失败及长时间失联行为明确；时钟不倒退；会话、调度、缓存和评分使用相同时间基础。测试无需真实外部授时，既有纯函数显式时钟参数保持可注入。

再运行完整回归，在本地核对真实授时一致性、公告发布时间与新采集时间、任务执行与日期展示。单独核查历史字段未被平移。服务器部署只提供后续发布前的验证条件，此设计评审不授权生产更新。

本文件待用户评审；评审通过后再编写实施计划并选择执行方式，当前不代表统一时钟已实现。
